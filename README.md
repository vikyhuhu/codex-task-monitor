# Codex Task Monitor

轻量的 macOS 菜单栏工具，汇总本机 Codex 任务的运行、待处理和本轮结束状态。Swift + AppKit/SwiftUI，使用系统 SQLite，无第三方运行依赖、服务器或模型调用。

## 使用

需要 macOS 13 或更新版本，以及已经运行过任务的 Codex 桌面应用。

```sh
./scripts/install.sh
```

安装到 `~/Applications/Codex Task Monitor.app` 并启动。菜单栏固定使用 `🔵 / 🟠 / 🟢` 三种灯，分别表示运行中、待处理、本轮结束待查看数量。待处理包含等待输入、失败、中断和状态待确认，展开列表保留具体原因；点任务打开对应 Codex 会话。无法读取最新数据时显示 `🟠 状态不可用`，不显示可能已过期的计数。

- 面板支持再次点击菜单栏、按 Esc、点击面板外、切换应用或点击右上角“收起”按钮关闭；关闭面板后后台监控继续运行。
- 面板与菜单栏保留 12 点间距，靠近屏幕边缘时自动调整位置，使用菜单栏按钮所在显示器的可用区域。
- 面板底部提供“开机自启动”开关（默认不自动开启）。开启后由 macOS 在登录时启动应用，无需再次寻找文件；关闭后停止自动启动，但当前监控继续。状态来自系统登录项；若需要系统批准，点击旁边的“系统登录项”完成设置。建议先通过上面的安装脚本安装到固定位置，再开启；系统中修改后，再次打开面板会同步状态。
- 首次启动收集近期仍在运行的任务和之后新运行的任务，历史已结束任务不自动加入。
- “查看今天的任务”会纳入当天开始的任务；不会发送历史通知。
- 已结束任务会同步 Codex 本机已读状态，通常在查看后 5–15 秒移出；数据缺失或格式不兼容时保留计数，仍可手动清除。从面板或通知成功打开已结束任务后也会立即移出。
- 已读同步兼容旧版未读列表及新版 `electron-thread-read-state-v1`。浏览器插件查看任务后，只要已读状态同步到本机文件，也会自动移出。新版数据包含多个账号或多个本地主机时，因无法确定当前作用域而保留任务，可手动清除；不读取认证令牌来推断账号。
- “清除已结束”或任务右侧的 × 将本轮移出列表，下次运行自动回来。
- 声音提醒默认开启：任务变为待查看、等你处理、失败、中断或状态待确认时，按类别播放声音：本轮结束用 Glass 单音，等你处理用两声 Tink（间隔 0.12 秒），失败/中断/状态待确认用 Basso 低音。同批只播放最高优先级：异常 > 等你处理 > 本轮结束。运行中、重复刷新和启动历史不响；已清除任务不再提醒。面板可关闭声音并分别“试听”三类声音，偏好会保留；关闭声音或播放新提示会取消尚未播放的第二声。声音直接本地播放，无需系统通知授权，受系统音量/静音影响，不依赖通知横幅或专注模式。
- 在面板中点“开启系统通知”，允许 macOS 通知权限后，结束、等待输入和中断等变化会通知一次。同一次刷新中的变化合并提醒。
- 启动时不补发旧通知，未查看任务仍留在面板。点击通知打开该任务；合并通知打开首个任务。
- 退出后不监控；已开启自启动时，下次登录会恢复监控。

## 状态含义与边界

| 状态 | 依据 |
| --- | --- |
| 运行中 | `task_started`，此后有近期日志活动 |
| 本轮结束 · 待查看 | 同一轮的 `task_complete`，**不代表任务验收通过或目标全部实现** |
| 等你处理 | 直接调用 `request_user_input` / `request_user_input_async`，直到后续用户消息或新一轮开始 |
| 已中断 | `turn_aborted` |
| 执行失败 | 显式 `task_failed`；普通工具报错不会将整项任务判失败 |
| 状态待确认 | 运行中超过 15 分钟无日志，或日志暂时不可读；不等于卡死 |

此版本只读 `$CODEX_HOME/state_*.sqlite`、它引用的 JSONL 日志，以及 `.codex-global-state.json` 中的本机未读列表（旧版 atom 或新版按账号、主机分组的状态），默认目录为 `~/.codex`。**这些是内部数据格式，Codex 升级后可能需要适配。** 当前数据库不兼容时显示状态不可用并保留旧列表，不伪造成功。

仅统计未归档的本机根任务，排除子 Agent。首次扫描默认覆盖近 24 小时有数据库更新的任务，此后覆盖监控开始时间以来更新过的任务；更早且无更新的长期任务可能不出现。日志不包含开始事件的任务不会被推断为完成。

等待识别有明确边界：纯文本提问、权限审批、登录/外部服务等待，以及嵌套在 `exec` 中的提问，不能保证识别。不会通过扫描工具代码中的关键词判断等待状态，以免把测试数据和文档误判为真的提问。异步可选问题也可能标为待处理；打开任务查看上下文即可。`task_failed` 是兼容支持，目前本机实测日志主要提供开始、结束、中断事件。

应用只保存监控起点、移出列表的任务标识和声音偏好到自己的 UserDefaults；自启动由 macOS ServiceManagement 管理，仅在操作开关时注册或移除。不修改 Codex 数据、不读取认证令牌、不上传任务内容。系统通知显示任务标题，请根据锁屏隐私偏好调整通知预览。

## 开发与验证

安装 Apple Command Line Tools 后：

```sh
./scripts/check.sh
.build/release/CodexTaskMonitor --snapshot
```

自动检查涵盖生命周期、旧轮结束事件、等待输入、误报防护、超时、中断、工具错误、JSONL 半行/损坏/截断、SQLite 过滤和数据源不可用。使用独立检查程序，兼容没有完整 Xcode/XCTest 的 Command Line Tools 环境。

`check.sh` 还验证自启动注册/移除、失败反馈、待批准和外部状态同步（使用模拟服务，不修改机器登录项），以及应用构建、签名和 Info.plist。

默认使用 Swift 工具链的默认构建引擎。若工具链的 Swift Build 引擎报告 `Unknown error parsing property list`，且支持 native 引擎，可临时执行 `CODEX_MONITOR_BUILD_SYSTEM=native ./scripts/check.sh`（安装脚本也支持该变量）。native 已被新工具链标记为弃用，仅作为此类环境问题的兼容选项。

可选运行 `./scripts/check-popover.sh` 检查菜单栏间距、屏幕边界、面板关闭、Esc、内外点击和重复开关（需要本机桌面会话，会短暂显示测试面板，不在 CI 中执行）。

可选运行 `./scripts/check-sounds.sh` 实测双音播放与取消（会发出短音，需要本机音频会话，不在 CI 中执行）。

`--snapshot` 仅输出状态计数，不输出标题、聊天内容或路径。构建产物在 `dist/`；GitHub Actions 在 PR 和 main 上运行同样检查并保存 app ZIP。构建的是运行架构版本，CI 的下载产物架构取决于 runner。

本地应用为临时签名，未进行 Apple Developer ID 签名或公证。跨机器分发可能遇到 Gatekeeper 限制。不要为此关闭系统安全设置。此工具不需要云端“网站部署”。

## 卸载

先关闭“开机自启动”（或从系统登录项移除），再在菜单中退出并删除 `~/Applications/Codex Task Monitor.app`。可选执行 `defaults delete local.codex-task-monitor` 清理自身偏好，不影响 Codex。
